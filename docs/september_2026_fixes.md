# Проверка проблем сентября 2026

Проверено 21.09.2026. Исправления находятся в локальном рабочем дереве;
на production не установлены. OAuth, данные Telegram и production SQLite не изменялись.

## Исправления кода

- Nest: модель иногда возвращала полную фразу в `details`, хотя её начало уже
  находилось в `lead`. Повтор начала удаляется перед проверкой и рендерингом.
- Полезное: отказ Bot API при удалении оставляет публикацию в индексе,
  объясняет ручное удаление и повтор `/useful delete <ID>` для согласования
  индекса, поиска и связей с исходниками. При частичной операции указывается
  число уже удалённых/отсутствующих частей. Подтверждение действует на одну
  попытку и не перехватывает последующие сообщения после ошибки.
- Заготовки: счётчик сбрасывается внутри каждой группы, порядок от старых
  записей к новым сохранён.
- Calendar: `invalid_grant` получает понятную инструкцию повторной авторизации;
  токен сохраняется атомарно с правами 0600, ошибка сохранения не игнорируется.
- Control: bootstrap, справочные тексты и проверки конфигурации используют
  Workspace, Nest, Test Lab. Старые переменные сохранены для совместимости.
  Закрытие старых топиков и обновление их закрепов в Telegram не выполнялось.

- Inbox: отказ удаления публикации 750 произошёл 05.09 в 10:25; 06.09
  оставшееся подтверждение поглотило новый список `#tasks` и повторило запрос
  «Удалить или Отмена». Отмена освободила ввод. Это основание для исправления
  жизненного цикла подтверждения.
- Calendar: 16.09 в 08:10 после кандидата №18 показано
  `refresh Google OAuth token: oauth2: "invalid_grant" "Bad Request"`.
  Google Auth Platform проекта `sova-calendar-499818` показывает External / Testing;
  кнопка Publish app недоступна до завершения Branding. Это вероятная причина
  истечения refresh token; точную историю отзыва токена без Google установить нельзя.
- Задачи: 17.09 «Оплатить ГПТ» создано в 09:36 и 12:26.
  General содержит исходный `#task` от 09:36:01, Inbox — исходный `#tasks`
  от 12:26:01 с тем же названием. Второй результат помечен отменённым.
  Наблюдения соответствуют двум разным источникам, а не повтору одной доставки.
  Если жалоба относится к другой паре сообщений, нужны их ссылки.
  Глобальная дедупликация по названию не вводилась: одноимённые самостоятельные
  задачи допустимы.

## Проверки и продолжение

`go test ./...`, `go vet ./...`, `git diff --check` пройдены.
Есть регрессии для повторов текста, групповой нумерации, отказов и частичного
удаления, последующего повторения операции, освобождения Inbox и конфигурации Control.

VM `sova-prod` найдена работающей в проекте `project-8c5dc42c-aa6d-4533-806`,
зона `us-central1-a`. Прямой SSH на сохранённый IPv6 вернул `No route to host`.
Браузерный SSH дошёл до подключения, после чего управление браузером стало
недоступно; выполнение команд на VM не подтверждено.

После восстановления доступа:

1. Завершить Branding и согласовать перевод OAuth-приложения из Testing в Production.
   Этот переход меняет доступность авторизации для аудитории приложения.
2. Повторно выполнить `sova google-login` с прежним аккаунтом и клиентом,
   установить токен в серверный `SOVA_GOOGLE_TOKEN_PATH` с владельцем сервиса
   и правами 0600. Каталог должен разрешать сервису атомарную замену файла.
3. Провести release gate из `docs/releasing.md`: резервная копия, точный commit,
   сборка, установка, doctors, журнал и проверка функций. После этого обновить
   существующий индекс Заготовок без `--reset`.
4. Повторить Approve исходного кандидата №18 только если событие по-прежнему нужно.
5. В Control оставить Workspace, Nest, Test Lab; старые топики можно закрыть
   с сохранением истории. Не удалять историю.

Источники ограничений:
[Telegram deleteMessage](https://core.telegram.org/bots/api#deletemessage),
[Google refresh token expiration](https://developers.google.com/identity/protocols/oauth2#expiration).
